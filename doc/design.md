# Qubit Event Bus 0.12 architecture status

This page records the implemented 0.12 architecture. See [the implementation architecture overview](design.zh_CN.md), the [formal SPI design in English](spi_design.md), and its [Chinese version](spi_design.zh_CN.md).

The crate exposes typed synchronous and runtime-neutral asynchronous facades over object-safe `EventBusSpi` and `AsyncEventBusSpi` contracts. Provider discovery, selection, creation, and creation-time fallback use `qubit-spi`. The crate includes a synchronous bounded-queue local provider. It does not bundle Tokio, crossbeam, flume, RabbitMQ, Kafka, or Redis adapters.

The facade owns portable event processing: typed requests and envelopes, codecs, middleware, filtering, retries, ACK/NACK, dead-letter handling, ordering, diagnostics, and lifecycle coordination. The SPI is deliberately smaller and transports erased payloads, receives messages, settles provider-issued tokens, and closes provider resources. Capabilities describe provider-specific limits; runtime failures do not trigger silent provider failover.

Ordering is a provider contract. A subscription requesting `OrderingPolicy::PerKey` is admitted only when the provider declares `OrderingCapability::PerKey` or the stronger `PerSubscription`; a facade checks this before calling provider `subscribe`. The former subscription priority option has been removed because it had no provider or facade scheduling semantics.

`PublishReceipt` reports provider admission, not handler completion. `DestinationAdmissions` may be empty or contain accepted, filtered, and rejected destinations. A mixed result is still a successful receipt; retrying the whole event may redeliver it to accepted destinations. `publish_all` is best-effort and non-atomic. `EventId` is a portable event identity (UUID v4 by default); `qubit_id::Id` is only a bus-local subscription object ID. Sync and async middleware are separate types and a facade rejects middleware for the other execution model. Async subscription consumption is caller-driven and does not spawn a task, but its owned delivery futures use a bus-wide `max_in_flight` admission limit; different ordering keys may progress concurrently while a key remains ordered. Dropping `run()` pauses owned work for a later run or bus shutdown to resume.

`PublishReceipt::check_admission` evaluates only that receipt's reported admissions, with either an at-least-one-accepted or at-least-one-accepted-and-no-rejections requirement. It has no publication side effect and cannot undo or retry the original call. Per-facade `PublishMetricsSnapshot` counters report public publish attempts, errors, interceptor drops, opaque accepts, zero-destination receipts, and accepted/filtered/rejected destination totals. Fields are loaded independently, so a concurrent snapshot is not a transactionally consistent instant; none of these counts reports handler completion. A synchronous `Subscription` handle does not cancel on drop: callers must invoke `cancel()` or shut down the bus.

The local provider binds a topic name to one native Rust payload type while subscriptions are active. Its per-subscription queue capacity covers queued and unsettled deliveries; Retry preserves a delivery's reservation. Sync `EventBus::wait_for_idle` reports provider queue and settlement state, while `wait_for_received_deliveries` reports only work already received by that facade. The async facade exposes only the latter guarantee.

Settlement repeats with the same token and disposition must be idempotent; conflicting dispositions must fail. Async settlement may be retried after cancellation with that same token. `Immediate` shutdown stops intake and drops not-yet-started queued work, but waits for active user code, settlement, receiver close, and provider shutdown so errors can be returned. It cannot forcibly interrupt a running Rust handler. Synchronous graceful shutdown uses one background coordinator per bus: the caller's deadline includes admitted publish/subscribe calls, worker drain and close, and provider shutdown. After `TimedOut`, the bus stays in `Closing`; new operations fail while the coordinator continues, and a later call can await its result or strengthen the attempt to `Immediate`. A blocked synchronous SPI method or handler can keep the coordinator alive. Async deadlines use `qubit-clock`'s `Timer`; the default is the standard monotonic timer and callers may inject another timer through `with_timer` or `with_config_and_timer`. Dropping an async shutdown future may leave provider side effects in progress, so providers must support idempotent retries.

Dropping an `AsyncSubscription::run` future pauses its owned delivery tasks for a later `run` call; dropping the subscription handle itself disposes the paused session and receiver. The provider must recover unsettled messages when a receiver is dropped. Call `AsyncSubscription::close().await` when deterministic async cleanup and close errors are required.

Publish terminal-error handlers receive `PublishFailureContext<T>`, which shares the payload and exposes event metadata without requiring `T: Clone`. They run after a direct SPI publish failure when no retry policy is configured, or after configured retries reach terminal failure—not for preflight errors. Applications that use advanced retry configuration depend directly on `qubit-retry`; this crate does not re-export it.
