# Qubit Event Bus 0.12 architecture status

This page is the English status entry for the 0.12 architecture. The complete formal SPI design is currently maintained in Chinese; this page intentionally does not translate that full document. See [the implementation architecture overview](design.zh_CN.md) and [the formal SPI design](spi_design.zh_CN.md).

The crate exposes typed synchronous and runtime-neutral asynchronous facades over object-safe `EventBusSpi` and `AsyncEventBusSpi` contracts. Provider discovery, selection, creation, and creation-time fallback use `qubit-spi`. The crate includes a synchronous bounded-queue local provider. It does not bundle Tokio, crossbeam, flume, RabbitMQ, Kafka, or Redis adapters.

The facade owns portable event processing: typed requests and envelopes, codecs, middleware, filtering, retries, ACK/NACK, dead-letter handling, ordering, diagnostics, and lifecycle coordination. The SPI is deliberately smaller and transports erased payloads, receives messages, settles provider-issued tokens, and closes provider resources. Capabilities describe provider-specific limits; runtime failures do not trigger silent provider failover.

`PublishReceipt` reports provider admission, not handler completion. `publish_all` is best-effort and non-atomic. `EventId` is a portable event identity (UUID v4 by default); `qubit_id::Id` is only a bus-local subscription object ID. Sync and async middleware are separate types and a facade rejects middleware for the other execution model. Async subscription consumption is caller-driven and does not spawn a task, but its owned delivery futures use a bus-wide `max_in_flight` admission limit; different ordering keys may progress concurrently while a key remains ordered. Dropping `run()` pauses owned work for a later run or bus shutdown to resume.

Settlement repeats with the same token and disposition must be idempotent; conflicting dispositions must fail. Async settlement may be retried after cancellation with that same token. `Immediate` shutdown stops intake and drops not-yet-started queued work, but waits for active user code, settlement, receiver close, and provider shutdown so errors can be returned. It cannot forcibly interrupt a running Rust handler. Async deadlines use `qubit-clock`'s `Timer`; the default is the standard monotonic timer and callers may inject another timer through `with_timer` or `with_config_and_timer`.

Dropping an `AsyncSubscription::run` future pauses its owned delivery tasks for a later `run` call; dropping the subscription handle itself disposes the paused session and receiver. The provider must recover unsettled messages when a receiver is dropped. Call `AsyncSubscription::close().await` when deterministic async cleanup and close errors are required.

Publish terminal-error handlers receive `PublishFailureContext<T>`, which shares the payload and exposes event metadata without requiring `T: Clone`. They run after a direct SPI publish failure when no retry policy is configured, or after configured retries reach terminal failure—not for preflight errors. Applications that use advanced retry configuration depend directly on `qubit-retry`; this crate does not re-export it.
